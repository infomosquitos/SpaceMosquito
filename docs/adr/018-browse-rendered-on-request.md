# ADR-018: Browse Pages Rendered on Request from content.md

- **Status:** Accepted
- **Date:** 2026-10-22
- **Related:** [ADR-015](015-saved-page-format-with-markdown.md) (saved page format; superseded for `index.html` and HTML navigation files), [ADR-016](016-sqlite-only-distribution.md), [issue #5](https://github.com/infomosquitos/spacemosquito/issues/5) (link page references to local copies), [`dev/README.md`](../../dev/README.md) (browse)

## Context

Per ADR-015 every saved page directory holds a generated `index.html` next to `content.md`, `raw.html`, `metadata.json` and `assets/`. `internal/catalogindex` also generates `saved/index.html`, `saved/<SPACE>/index.html` and `saved/<SPACE>/tree.js` (page tree sidebar and content search for every page).

- **Stale copies.** Each browse UI change (rendered images, page tree, sidebar, search bar) only reached existing pages after `spacemosquito reindex --content`. A normal crawl skips unchanged pages, so their `index.html` keeps the old look.
- **Two sources.** `content.md` (and `pages.content`) is the source for search, MCP and agents; the generated `index.html` is a second rendering of it that can drift.
- **Browsing already needs the server.** Browsers do not let extensions open `file://` pages, so 📖 in the extension opens `serve`'s read-only `/browse/` route; content search there calls `/api/search`. Direct `file://` browsing is a secondary path.
- **Workarounds.** Sidebar and search live in `tree.js` so tree changes do not rewrite every page; Confluence page links inside content (issue #5) cannot be resolved to local pages in static files saved before their targets.

## Decision

`serve` renders the browse UI on request from `content.md`, `metadata.json` and the database; the saved catalog no longer contains generated HTML for Storage Format pages.

| Area | Choice |
|------|--------|
| Rendering | `/browse/` (spaces), `/browse/<SPACE>/` (page tree + content search, `?q=` prefill) and `/browse/<SPACE>/<page dir>/` (page) are rendered per request. Page body: `content.md` via goldmark (GFM, hard wraps, raw HTML escaped); title and Confluence URL from `metadata.json`; empty parent pages list their children. Tree from `parent_confluence_id` (`catalogindex.BuildTree`). |
| Sidebar and search | Rendered server-side into each page (tree with current page and its path open, title filter, expand/collapse all, page count and last crawl, top-bar quick search). Behaviour comes from one embedded static JS/CSS bundle under `/browse/.static/`. Replaces `tree.js`. |
| Files under a page dir | `assets/**` and `content.md` served as files; `raw.html` served as `text/plain` (Confluence source, never executed); `.../index.html` redirects to the page dir so old bookmarks work; nothing else, no directory listings. |
| On-disk output | Crawls, `crawl-page`, `reindex --content` and saved-catalog import no longer write `index.html` for Storage Format pages, nor `saved/index.html`, `saved/<SPACE>/index.html` or `tree.js`. `saved/index.md` and `saved/<SPACE>/index.md` stay (Markdown trees for agents). Per page: `content.md`, `raw.html`, `metadata.json`, `assets/`. |
| Browser-fallback pages | Keep their `index.html`: it is the extracted HTML their `content.md` is derived from (`internal/contentmd/render.go`). Displayed through the same renderer from `content.md`. |
| Offline copy | `spacemosquito export-html [--space KEY] <dir>` writes a static, `file://`-browsable copy (root, spaces, pages with sidebar, tree and title filter; assets copied; no content search). Refuses a target inside the saved catalog or a non-empty directory. |
| Search results | REST/MCP search `file_path` points to `{file_dir}/content.md` (always present, readable by agents); `browse_url` unchanged. |
| Upgrade | `reindex --content` deletes HTML generated by earlier versions (catalog `index.html` files, `tree.js`, `index.html` in Storage Format page dirs only). The renderer ignores leftovers. |

## Alternatives considered

| Option | Why not |
|--------|---------|
| Keep generating static `index.html` (ADR-015, today) | Every UI change needs a reindex; static copies drift from `content.md`; sidebar/search need the `tree.js` workaround |
| Render on request **and** keep writing static files | Two outputs to maintain; static files still go stale between reindexes |
| Frame shell (tree page + iframe with page files) | No per-page URLs, odd back button; Confluence links blocked inside frames |
| Rely on a browser Markdown viewer extension | Depends on each user's browser setup; no tree, search or images by relative path |

## Consequences

- **Easier:** UI changes reach every page with an upgrade plus a restart of `serve`, with no reindex. `content.md` becomes the single source for viewing, search and agents. Confluence page links can be resolved to local copies at render time (issue #5). There are fewer files per page.
- **Harder:** browsing needs `serve` running, or a manual `export-html`. The README promise of "browse offline from `saved/index.html`" and the Homebrew caveat change. Render errors surface per request, so the handler needs tests for traversal, content types and missing files.
- **Contract:** ADR-015 is superseded for `index.html` and the HTML navigation files. Its `content.md` / `raw.html` / `metadata.json` / `assets/` contract stays.
- **Implemented in v0.8.0:**
  - A new `internal/browse` package (handler, templates, embedded static bundle, export).
  - Remove the HTML writers from `internal/scraper`, `internal/catalogindex`, `internal/contentmd` and `internal/bootstrap`.
  - Change the search SQL to return `file_dir`.
  - Add the `export-html` CLI command.
  - Update the docs: README, INSTALL, `dev/README.md` and the cask caveats.
  - Ship as v0.8.0.
